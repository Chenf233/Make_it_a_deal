# 功能模块开发流程

## 1. 适用场景

用于新增或修改可独立调用的能力：

- Camera、Face Recognition、Scanner。
- Motor、Buzzer/Light、Electromagnet、Cabinet Controller。
- Python-C IPC、`station_iotd` 和 Huawei IoT 传输。
- 未来新增的硬件、CV、原生或外部服务适配器。

如果任务的核心是“多个能力和数据库怎样完成业务”，应使用
[FastAPI 增量开发流程](fastapi-development.md)。

## 2. 开始前定义边界

用简短文字回答：

```text
模块提供什么能力？
调用者输入什么？
调用者得到什么？
模块自己拥有什么资源和状态？
模块明确不负责什么？
```

示例：Huawei IoT 模块负责连接和发送指定 A/B 绝对值，不负责决定什么时候累计、
累计值存在哪里或哪项业务触发上报。

## 3. 盘点必要资产

按需读取：

- 模块公开入口和实现。
- 模块常量、配置和测试。
- 直接调用者。
- 线程、锁、子进程、GPIO、摄像头等资源。
- 目标平台和外部依赖。

跨语言模块额外检查：

- Python API。
- IPC 消息和关联方式。
- C 入口和退出行为。
- 第三方 SDK 边界。
- Makefile、动态库、证书和运行路径。

不要因为模块位于 `services/` 就假设它已经独立；先检查是否反向访问 FastAPI、
Application 或业务数据库。

## 4. 固定外部契约

实现前明确：

- 构造和配置方式。
- `start/init` 与 `stop/close`。
- 输入、输出和数据单位。
- 同步或异步。
- 超时、取消和幂等性。
- 并发和线程安全。
- 状态查询。
- 能力层错误。
- 平台要求和安全默认值。

FastAPI 应依赖该契约，不依赖内部 GPIO、线程、SDK 回调或私有状态。

## 5. 实现规则

- 内部可以使用最适合的 Python、线程、`asyncio`、OpenCV、GPIO、C 或 SDK 方案。
- 不访问 SmartStation 业务数据库。
- 不导入 Router 或 Application。
- 不决定跨模块业务顺序。
- 新模块不得在导入时触碰真实硬件或启动后台执行单元。
- 有资源的模块必须提供安全停止方法。
- 错误通过异常、结果或事件明确暴露，不要求调用者解析日志。

## 6. 验证阶梯

| 模块类型 | 本地验证 | RDK/真实环境验证 |
| --- | --- | --- |
| 纯 Python | 单元测试、边界值、并发 | Smoke Test |
| CV | 固定图片、Dummy Camera、输出结构 | 真实摄像头、模型和性能 |
| GPIO | Fake GPIO、引脚映射、互斥和状态机 | 方向、电平、动作和安全停止 |
| Python-C | Fake Process、协议和超时测试 | 编译、`ldd`、真实进程和退出 |
| 云端 | Fake 事件、重连和排队逻辑 | 鉴权、发布、断线恢复和控制台确认 |

先执行低成本验证，再准备设备验证。不得用桩测试证明真实 GPIO、AArch64 链接或云端
产品模型已经正确。

## 7. 设备验证准备

设备难以访问时，在代码同步前准备：

- 唯一、可复制的运行命令。
- 所需环境变量和配置文件。
- 是否要求停止 SmartStation 或独占设备。
- 是否会移动机械结构或修改业务数据。
- 成功标准和预期输出。
- 失败时保留的日志和状态。
- 超时、停止和安全恢复方式。

危险或真实集成测试应默认跳过，并要求显式环境变量启用。

## 8. 向 FastAPI 交付

模块完成后，应用侧只需知道：

```text
怎样构造和启动
怎样调用
怎样查询状态
怎样停止
有哪些能力层错误
哪些行为仍等待 RDK 验证
```

如果集成要求 Application 读取模块私有变量或直接操作底层引脚，说明模块契约尚未
完成，应先修正接口。

## 9. 完成状态

按实际证据报告：

1. 接口完成。
2. 本地验证完成。
3. RDK/真实环境验证完成。

设备不可用时，允许以“接口和本地验证完成，RDK 验证入口已准备”结束。
